# WearEngine Bridge — состояние проекта

Основные исходники выделены в самостоятельный проект по запросу пользователя.
Лицензия MIT выбрана пользователем. По его запросу история проекта сведена
к одному начальному коммиту, публичная версия начинается с 0.1.
Публикацию пользователь выполняет сам.
Не обращаться к телефону через ADB и не выполнять publishing/uploading tasks.
Ключи и пароли остаются внешними; не читать/выводить их и не копировать в проект.

- Исходный Frida scope-hook успешно проверен в PhoneService: observe возвращал
  false, bypass позволял getBondedDevices/registerListener. Установка HAP не проверена.
- Пользователь подтвердил успех предварительной LSPosed-сборки после завершения Frida.
  Свежих runtime-логов не предоставил; конкретный classId/loader этого успеха неизвестен.
- ClassHookRegistry и политика допуска любых клиентов перенесены без изменений.
- 0.1 (code 1): убран Timer/heartbeat; подробные логи и per-call bookkeeping
  включаются через генерируемый BuildConfig.DEBUG только с --diagnostic.
  READY и ошибки остаются; алгоритм установки и scope-решение прежние.
- build.py не зависит от прежней рабочей области, сертификата, предыдущего APK,
  конкретного пользователя или фиксированных путей SDK/JDK. Внешний API 82
  закреплён checksum; по умолчанию строится unsigned APK.
- Обе сборки прошли по 32 JVM-проверки, ZIP/manifest/DEX/выравнивание и проверку
  диагностического флага в Windows/Python 3.11/JDK 8/SDK 35/Build Tools 36.1.0.
  Текущая 0.1 пока не проверена на телефоне. Linux/macOS не проверены.

## Следующий шаг

Пользователь подтвердил выбор Python-сборки; переход на Gradle не требуется.
Workflows пока не добавлять. Для проверки 0.1 собрать и подписать тем же внешним
ключом, установить модуль и перезапустить Health. Предварительную сборку с
более высоким versionCode сначала удалить; Health не удалять. Проверить getDevices без Frida,
затем отдельно переходить к установке HAP. Не объявлять локальные тесты
подтверждением runtime-работы или совместимости с другими версиями Health.

## Перенос на другой компьютер

Перед первым коммитом проверены все 14 исходных/документирующих файлов: нет
персональных абсолютных путей, ссылок на прежний workspace или встроенных
значений ключей/паролей. README содержит только PATH_TO_* примеры. build.py
принимает пути параметрами; SDK/JDK могут определяться стандартным окружением.
Ключ подписи не входит в репозиторий. Кеш зависимости и результаты сборки
игнорируются. Перехват не менялся при перенумерации; обновлены manifest и
документация. Новых runtime-проверок нет.

На новом компьютере установить Python/JDK/Android SDK по README, собрать через
build.py. Подпись для обновлений настроить отдельно тем же ключом; его перенос
пользователь выполняет самостоятельно. Автоматические релизы отложены.

## Нумерация

По явному запросу пользователя versionName 0.1 и versionCode 1: публичная
нумерация полностью начинается заново. Для перехода с предварительных сборок
с более высоким versionCode потребуется удалить прежний APK модуля.
Исходники, тесты, build.py, assets и res идентичны исходному коммиту версии
0.5.1; менялись только manifest и документация. Это перенумерация без отката кода.
Следующие версии должны увеличивать versionCode. build.py берёт
версию из manifest для BuildConfig, имён APK и отчёта; вручную менять её в
других исходниках не требуется. Старые локальные build/dist сохраняются и
не входят в Git. Workflows и публикация по-прежнему не выполняются.
